# 批判性计划审查 · critical-plan-review

一个简单的中文提示词 Skill：让主智能体实际创建三个独立专家子智能体，对实施计划或开发方案进行有依据的批判性审查。

## 三位专家

- **复杂度审查专家**：重点查找没有当前需求支撑的复杂设计，提出仍能完整满足需求的精简方案。
- **需求覆盖审查专家**：检查遗漏、误解、擅自扩展，以及精简是否损害必要功能。
- **可执行性与验收审查专家**：结合现有代码、依赖与证据，检查方案能否落地、验收是否贴近真实使用。

三位专家必须对应三个不同的真实子智能体 ID。主智能体负责核实、汇总，不计入这三个专家；禁止由单个模型扮演三个角色代替。

## 安装到 Codex

解压分享 ZIP，将其中的 `critical-plan-review` 文件夹放入个人 Skills 目录。也可以下载本仓库，仅将 `SKILL.md` 放入同名文件夹：

- Windows 默认位置：`%USERPROFILE%\.codex\skills\critical-plan-review\SKILL.md`
- macOS / Linux 默认位置：`~/.codex/skills/critical-plan-review/SKILL.md`
- 如果设置了 `CODEX_HOME`，使用该目录下的 `skills/critical-plan-review/SKILL.md`。

安装后重新打开对话；若尚未识别，再重启 Codex。已有同名 Skill 时，先确认内容再决定是否替换。

## 使用

提供原始需求、待审查计划和必要项目文件，然后直接说：

```text
使用 $critical-plan-review 审查当前实施计划，重点检查过度复杂，只输出审查意见，不修改文件。
```

需要审查后修订计划时：

```text
使用 $critical-plan-review 审查当前实施计划，并根据有依据的意见修改计划、说明理由；不要开始具体实现。
```

## 执行边界

- 需要运行环境实际提供创建三个独立子智能体的工具；Skill 本身只是提示词，不提供这些工具。
- 默认只执行一轮审查。专家独立、只读地检查相同原始材料，每项问题说明位置、依据、影响和最小修改建议。
- 主智能体依证据处理分歧，并报告三个子智能体的实际 ID 和完成情况；不为批判而捏造问题。
- 审查或修订计划不等于开始实施。工具不可用或某位专家未完成时，必须如实报告，不能声称三专家审查已完成。
- 没有脚本、安装器、额外依赖或配置系统。仓库与分享包只包含通用 Skill 与说明，不包含私人项目数据、配置或记忆。
